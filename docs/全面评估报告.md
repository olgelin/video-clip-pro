## 一、动画问题修复（已解决，端到端验证通过）

用户反馈三个问题，全部定位根因并修复：

| 问题 | 根因 | 修复 | 验证 |
|---|---|---|---|
| 画面静态 | `data-composition-id="quote_hero"` 硬编码，与 `__timelines["beat-N"]` 不匹配 → HyperFrames 找不到 timeline 不 seek | 改为 `data-composition-id="beat-{scene_idx}"` | 帧间差异 0%→1.7-6.3% |
| 背景粒子没了 | Three.js 用 CDN importmap（ES module），file:// 下 CORS 阻止 + headless 无网络 | 下载 three.min.js(r147 UMD) 内联，全局 THREE，删 importmap/import | 粒子 0%→0.7-3.8% |
| 人物窗口没了 | 场景 z-index:10 盖住 pip-win z-index:6 | pip-win→15, pip-frame→16 | 肤色 1% 稳定 |

**关键铁律**（已写入 skill pip-pipeline-v89）：
- HyperFrames runtime 用 `window.__timelines[data-composition-id]` 捕获 timeline（`d[h]`），seek 用 `totalTime(r)`。三者必须一致：`data-composition-id` == `__timelines` key == host 引用 id。
- timeline 必须 `{paused:true}` + 注册，**无 tl.play()**（runtime seek 驱动）。
- headless 渲染无网络：GSAP/Three.js 都必须本地内联，不能 CDN。

## 二、creator-playbook 综合评估（值得借鉴处）

**项目**：github.com/chukeru1993/creator-playbook（Ruby，21 stars，活跃更新）
**本质**：面向中文知识视频的「开源方法资产库」，核心思想是**方法资产 vs 项目素材分离**。

### 值得借鉴（按价值排序）

1. **分镜计数单位：一个 Scene = 一个观众能带走的结论**（高价值，直接借鉴）
   - 我们的语义分镜 prompt 现在按"话题/信息点/转折点"切，可以升级为"结论优先"。
   - 切镜理由必须同时满足：①新内容留下不同结论；②现有空间拓扑无法表达。
   - "旁白换句""需要变化""这一拍短"都不是切镜理由——这能治我们"场景碎片化"。

2. **音画契约（beat_registry）**（高价值，直接借鉴）
   - 逐 cue 映射：旁白命题、屏显对象、字幕锚点、动作、终态、证据类型。
   - "画面不能说 A、旁白说 B、字幕再说 C"——先锁旁白事实，再决定对象和动效。
   - 我们已有 final_start/final_end + 字幕，可升级为结构化契约。

3. **资产管理精细化**（高价值，直接回应核心诉求）
   - "通用规则经多项目验证后才回收；不把项目专属事实写进公共规范"。
   - 这正是用户要的"哪些写入知识库、哪里作为经验"的答案。

4. **视觉契约分层（shared_design vs project_scope）**（中价值）
   - 我们的 scene_system.md 是共享设计，可加"项目视觉契约"层（PROJECT-VISUAL-CONTRACT）。

5. **语义音效 Spotting**（中价值，新能力）
   - 音效是"第三条信息通道"，不是每个动画配声。密度档位 sparse/balanced/dense。
   - 我们目前无音效，是新能力，但需要音效库（catalog）。

6. **颜色纪律（语义色 vs 装饰色）**（中价值）
   - Coral=风险、Green=解决、Blue/Violet=内容属性，不能当装饰色。
   - 我们已有类似铁律（绿=增长、红=警告、金=洞察），可更严格。

### 不直接借鉴（避免照搬）

- Ruby 语言、Studio 可视化编辑器——我们是 Python + LLM 驱动，架构不同。
- 具体的 token 值（暖近黑 #181916 等）——我们已定深色蓝紫，不必改。

| **配音/克隆/音乐** | 未部署 | — | 见下方"未部署能力"评估。 |

### 未部署能力评估（配音/克隆/音乐）

用户提到"配音、克隆、音乐等很多都是本地部署"，但当前 config.yaml 里：
- **配音（TTS）**：edge 云端默认，本地 piper/neutts 未启用。
- **声音克隆**：未见专门部署（elevenlabs voice_id 是云端 API）。
- **音乐生成**：未见部署（记忆里提到的 Suno/HeartMuLa 是云端 API）。

**建议**：
- 配音：当前 edge 免费且音质可接受，维持即可；若需要本地化，优先 piper（快、轻量）。
- 克隆/音乐：本地部署成本高（GPU/模型大），云端 API（Suno/elevenlabs）更省事，暂不值得本地化。

**9 个正常**：健康巡检、AI热点采集、视频经验沉淀、知识蒸馏、飞书同步、记忆整理、AI周报、自动链接、Video Ops 生产。

### 4.2 发现的环境问题

1. **pip 环境混乱**：全局 pip → Python 3.14，core venv → 3.12。系统提示"python3=missing, python=3.12.11, pip→python3.14"。这会导致脚本用错环境。
2. **C盘清理脚本超时**：weekly_cleanup.sh 命令本身正常（pip cache purge、find 都 exit 0），但整体阻塞，可能是 `rm -rf` 大量临时文件慢，或 `df` 在特定环境卡住。

### 4.3 知识库/经验管理精细化建议

用户核心诉求："哪些需要写入知识库、哪里作为经验，没有精细化地管理"。

**借鉴 creator-playbook 的资产管理原则，建议分层**：

1. **通用方法（该沉淀到 skill）**：多项目验证过的规则 → 写入 skill（如 pip-pipeline-v89 已记录）。
2. **项目专属事实（该留在项目）**：具体项目的口播稿、时间码、素材路径 → 留在项目 docs。
3. **环境事实（该写入 memory）**：机器配置、路径、工具版本 → 写入 memory（已有部分）。
4. **经验陷阱（该写入 skill 的 pitfalls）**：调试中踩的坑 → skill 的 pitfalls 段。

**当前缺口**：
- cron 任务报错没有自动告警（用户不知道 2 个任务报错了）。
- skill 记录偏"流水账"，缺少"什么情况下触发、什么不该做"的结构化。
